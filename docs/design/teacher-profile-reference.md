# Teacher Profile reference

The Teacher Profile route uses the supplied composition: a lavender illustrated heading and paper note, an overlapping identity card, a personal-information form above additional details on the left, and password/security/account-action cards on the right. The existing Teacher Home sidebar and profile menu are reused without a profile-specific variant.

The classroom and teacher artwork reuse `Teacher Home Hero Banner Background.png` and `Teacher Illustration.png`. The default circular portrait crops the existing teacher illustration; an uploaded avatar takes its place. It is a decorative default rather than a claimed photograph. No new generated image was needed. The illustration recreates the reference's style rather than claiming a pixel-identical source image.

Names, email, account ID, assigned grades and avatar come from the signed-in account and existing `teacher_profiles` query. Profile name updates remain scoped to the caller's `users` row, then refresh the identity so the sidebar also receives the new name. Copy ID uses the actual auth user ID. Avatar uploads validate type, size and image decodability, use an owner-prefixed unique path in `teacher-avatars`, and confirm the profile row update before reporting success. Grades and unrelated profile fields are never included in an avatar write.

Email and role retain their previous read-only behavior. Teaching grades remain assigned by the administrator, as enforced by migration 006's existing trigger; selected and unselected grade boxes are disabled and explained. All actual assigned grades are displayed, including Kindergarten, Grade 5 and Grade 6. Language and timezone display the currently supported Filipino/Manila values without offering unsupported localization controls.

Password fields support individual visibility buttons, current-password verification, matching confirmation and the existing strength requirements. The verification client has isolated, nonpersistent storage and no token refresh or URL session detection; its temporary session is signed out locally. It cannot replace the main browser session or downgrade an existing MFA session. Password fields clear only on a successful provider update, and failures retain the draft without claiming success.

Account Security uses actual Supabase TOTP factors. Enabling requires QR enrollment and a verified six-digit code before the switch becomes enabled. Cancellation removes only the setup's pending factor. Restarting cleans only unverified factors named by this Teacher setup, leaving other factors alone. Disabling requires an authenticator challenge before unenrollment. Failed verification/cancellation remains recoverable in a native dialog with Escape/focus handling. Active Sessions explicitly shows only the current authenticated browser session; it does not invent a device history.

Account data export reads only the authenticated teacher's existing profile, lesson metadata and sent/reply records, then downloads JSON. It excludes auth tokens and passwords. There is no teacher self-deletion endpoint, so the unsupported delete action is replaced with a working Account Settings link, following the user's earlier preference to hide unsupported controls. No deletion service, schema change or elevated database access is introduced.

The design supports desktop/tablet/mobile layouts and a muted dark theme while inheriting the existing font family. Empty, loading and failed teaching profiles are distinct. Missing profiles disable avatar changes rather than reporting a nonexistent profile-row update as successful. Failed-profile retry controls stay outside the identity-card overlap. No live account changes were made while implementing or testing the page.
