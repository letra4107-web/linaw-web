# Teacher Messages reference

The Messages page follows the supplied purple classroom composition: a shallow illustrated heading and paper note, a rounded conversation list on the left, and an adjacent chat with date separators, incoming/outgoing bubbles, reactions, attachment cards and a bottom composer. The shared Teacher Home sidebar and profile menu remain unchanged.

The banner reuses the existing `Teacher Home Hero Banner Background.png` and transparent `Teacher Illustration.png`; the quotation and heading remain editable HTML. Participant avatars now use their actual uploaded Parent/Teacher profile photos through the scoped photo API, with initials for absent or broken images. Photos appear in the inbox, chat header, incoming/outgoing bubbles and recipient picker. See [message profile photos](message-profile-photos.md). No new generated images were needed for this page. The artwork recreates the reference's style; it does not claim a pixel-identical source image.

All contact names, children, grade levels, unread reply counts, messages, read receipts, reaction counts and attachment paths come from existing authenticated queries. Messages has its own roster cache key because the Students/Reports roster selections omit parent IDs. Roster, sent-message and reply queries explicitly include the signed-in teacher ID. Users/name lookups are limited to rostered parent IDs. Kindergarten and parents with multiple linked children are supported.

The four filter buttons represent supported data: all contacts, contacts with messages, unread parent replies and conversations with files. Search covers parent/child names and the latest message; conversation search also includes attachment names. Sorting supports latest messages and parent names. Unsupported teacher-to-teacher/system inboxes, presence badges and calls/video remain hidden. Teacher file sending is now supported through the existing private bucket after migration 050, with a 5 MB limit, supported document/image types, draft preservation and retry. The file filter includes both participants' attachments. Existing parent reply attachments remain accessible through private signed URLs; no fake file sizes, online statuses or conversations are added. See [conversation and file update](message-conversations-and-teacher-files.md) for installation and verification.

The existing teacher-message insert, reply read update, reactions RPC and realtime/polling subscriptions remain in use. History combines follow-up sends and replies for the selected parent, ordered chronologically. The reply reader supports attachment metadata and falls back to the older reply schema only for known missing-column errors; permission/transport failures remain errors with retry controls.

The native New Message dialog supports recipient search, Escape, focus containment and restoration. Selecting an existing recipient preserves their draft. Drafts are kept per parent for the current page session. Multi-child contacts have an explicit child selector. Sending captures the parent, child and draft; switching conversations or editing while a send is pending cannot redirect the message or erase a newer draft. A synchronous guard prevents duplicate Enter submissions. Failed sends retain the text. Enter sends, Shift+Enter inserts a line, and emoji insertion uses the current text selection. The composer has a 500-character limit.

Mobile uses a conversation-list/chat view with a back button. Tablet/desktop retain the two-panel layout. The full page uses document scrolling while the bounded conversation history scrolls independently, as a chat panel. Light and muted dark themes preserve readability. Loading, failed, unmatched and empty states are distinct. No backend, database structure or live account/message data was changed.
