# Teacher Notifications reference

The Teacher Notifications page follows the supplied composition: a shallow illustrated classroom banner and paper note; All/Unread/Read controls and Mark all read; a wide search field with date/type selectors; and rounded notification cards with pink/blue document illustrations, real content, timestamps, category badges and actions. The existing Teacher Home sidebar and its five navigation destinations remain in use. A shared mobile brand-text rule preserves readable contrast without changing sidebar structure.

The header reuses `Teacher Home Hero Banner Background.png` and `Teacher Illustration.png`. The title, paper note, bell accents and notice icons are HTML/CSS/SVG. No new raster asset was needed. The artwork recreates the reference's style rather than claiming a pixel-identical source image.

Cards use the existing authenticated `/notifications` service through `useNotifications`. Titles, read status, body/message values and timestamps remain real records. The existing reply trigger's `Tungkol kay …:` prefix is split into a subject and message excerpt; no child names, quotations, reply text or read-status dots are invented. A second distinct message field remains available in expanded/full details. Unknown types receive a System badge rather than a guessed message destination.

Search matches actual title/body/message/category text. Status, type and date filters work together and have a reset action. Today/7-day/30-day periods use Manila calendar-day boundaries and exclude invalid/future timestamps; All retains the service's returned window, including old records. Invalid dates have an explicit unavailable label. The existing 50-row API list limit is unchanged, so counts describe the currently returned, preference-filtered notices.

Tingnan opens the complete notice in a native dialog. Expanding an unread row or viewing its details uses the existing owner-authorized mark-read endpoint. The action menu supports full details, mark read and notification settings; unavailable mark-unread/deletion operations are not offered. Confirmed data updates drive status and counts; failed requests retain unread state and expose retry controls. Mark all read retains the existing backend semantics for the whole authorized account scope, including notices outside the current list/filter.

Details link only to known protected Teacher routes: Messages, Progress Reports, Lessons or Profile. The API does not return reliable conversation/deep-link identifiers, so message actions open the Messages area rather than claiming an exact reply/thread selection. Unknown/system notices still have complete details without a fabricated external destination.

Existing Teacher Settings display preferences continue to apply to optional notice categories and unread counts, while account/security and unknown notice types remain visible. Realtime invalidation and the existing foreground polling/focus/reconnect behavior remain intact. The layout supports desktop/tablet/mobile, full-text expansion, keyboard-accessible controls, light mode and muted dark surfaces. No backend, database, learner or live-account records were changed while implementing/testing this page.
