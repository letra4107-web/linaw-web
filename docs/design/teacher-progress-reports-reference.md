# Teacher Progress Reports reference

The Progress Reports page follows the supplied classroom composition: a shallow illustrated banner with an editable title and quotation, four pastel summary cards, an overall chart beside a reading-level donut, two learner highlight panels, and a compact student table. It reuses the Teacher Home sidebar and profile menu. There is no report-specific sidebar variant.

The header reuses `Teacher Home Hero Banner Background.png` and the transparent `Teacher Illustration.png`. `src/assets/teacher/report-illustrations.png` was generated with the imagegen skill as three transparent sticker illustrations: a report clipboard, a medal, and a reading child. ReportArtwork displays the three cells through an imported image so the assets work in compiled builds. Student portrait defaults reuse the existing `home-decorations.png`; these are decorative placeholders, not uploaded photos or inferred learner demographics. The artwork recreates the reference's style rather than using a pixel-identical source image.

Names, usernames, grade levels, reading levels, cumulative accuracy, completed activities and recent practice come from the existing authenticated data sources. The roster is explicitly scoped to the signed-in Teacher, and progress/session reads are restricted to that roster's child IDs. Session reads paginate so a highly active learner cannot hide another learner's latest practice. Empty rosters do not issue unrestricted progress queries.

The existing score and threshold calculations are retained: rounded `accuracy_sum / total_attempts`, target at 80% or higher, and support below 70% only when attempts exist. The table shows a dash for an unattempted score. The Active summary counts learners with attempts; the row status retains the existing active-versus-support classification. No historical growth percentages are invented. Weekly activity uses Monday midnight in Asia/Manila.

The 7-day/30-day period selects learners with a recent pronunciation-practice session; All includes every learner with attempts. The graph uses those learners' cumulative progress records, not reconstructed historical scores. Completion and Practice retain the previous class-relative calculations: completed activities and attempts compared with the highest totals in that cohort, averaged by grade. They are not curriculum completion percentages. The expandable chart explanation makes this limitation visible. Kindergarten, all returned grades, and additional reading levels are supported; the donut counts every rostered learner once.

Metric buttons filter the student table. Search matches name, username or child ID. Grade/level filters and pagination work together, including later pages beyond the initial five page buttons. Selection supports an indeterminate page checkbox, selected-only viewing and clearing. Names, highlight rows and action buttons open the existing native student details dialog with real practice, assignment and module queries. Selection does not change learner records.

Loading, unavailable and empty results have separate presentations and retry controls. Mobile keeps the full table in a labelled horizontal scroll region while the page uses the ordinary document scroll. The layout supports desktop, tablet, mobile, existing font preferences and a muted dark theme. No backend, database structure, learner progress or sidebar destinations are changed.
